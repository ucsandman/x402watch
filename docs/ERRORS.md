# Errors and lessons

- **2026-09-01 — Full probe (32k endpoints) died silently on Windows with exit 127.** Node 24 on Windows hits a libuv assertion (`UV_HANDLE_CLOSING`) under sustained socket churn; 1,500 targets ran fine, 32k did not. The scheduled run lives on a Linux GitHub Actions runner where 14,933 probes took 197 s. Locally, use `npm run probe:smoke` or `--max 1500`.
- **2026-09-01 - x402scan search returns HTTP 500 above `limit=20000`.** The first cron run crawled zero x402scan rows because the requested limit was 100,000. The resulting 20,000-row cap was temporary; see the 2026-10-02 fix below.
- **2026-09-01 - Price drift compared `accepts[0]` to `accepts[0]`.** A live 402 can list several payment options in a different order than the directory. The probe now picks the live option on the listed network before comparing amounts, so drift means a real price change, not option reordering.
- **2026-10-02 - An unpaginated search silently omitted catalog rows (issue #1).** Public upstream source confirms `public.resources.search` accepts no offset or cursor. Use `public.resources.list.paginated` with nested `pagination: { page, page_size }`, preserve search membership filters, and verify page lengths, unique resource IDs, and totals. A fixture with more than 20,000 rows checks the last endpoint. A second regression demonstrated that swallowing an x402scan failure wrote an empty snapshot and removed history; the run now aborts before either write. Lesson: a successful HTTP response is not evidence of complete discovery, and incomplete discovery must not be treated as delisting. Regression tests use synthetic catalogs and snapshots. Before publication, two authorized free catalog GETs confirmed the pagination shape; no endpoint probes, payments, or production snapshot writes were performed.
- **2026-10-02 - Offset pagination still overlapped under tied sort keys.** A later authorized discovery-only check found seven repeated IDs in the first two 100-row x402scan pages, so the completeness guard correctly stopped the crawl. The upstream query orders by `lastUpdated` without a unique tie-breaker. The local follow-up uses complete page-zero ID ranges: retain one sampled pivot, split the remainder with strict `<` and `>` filters, and require child totals plus the pivot to equal the parent count. Seven small free GETs verified the filters and measured listing categories; three more exercised the actual local crawler restricted to a 26-row group and returned all 26. No full crawl was repeated. Lesson: validate catalog coverage under tied ordering, not just the pagination envelope. Same-cardinality catalog churn still requires an upstream snapshot contract; full-catalog runtime and the scheduled probe budget remain release gates.
